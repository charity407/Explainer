# Explainer — Your Private, Offline Document Assistant

**Understand your documents. Keep your AI on your device.**

Explainer is a local AI document assistant designed to help people understand complex documents, identify important information, and decide what to do next. Powered by an on-device LLaMA 3.2 1B model through the QVAC SDK, Explainer is designed to provide AI-assisted document understanding without relying on cloud-based AI inference APIs.

## Overview

Important information is often hidden inside lengthy documents, complicated terminology, and detailed instructions. Explainer helps users make sense of that information by turning document text into understandable explanations and actionable insights.

Users can analyze document content, identify key points, and ask follow-up questions in natural language.

Unlike cloud-dependent AI assistants, Explainer uses a local language model through the QVAC SDK, with the goal of keeping document processing on the user's device.

## The Problem

People encounter documents containing unfamiliar terminology, complex language, detailed requirements, and information that is easy to overlook. Understanding these documents can take time and may require assistance that is not always available.

Cloud-based AI tools offer a convenient way to interpret documents, but sharing sensitive information with external services can create privacy concerns. These tools may also be inaccessible when internet connectivity is unreliable.

## Our Solution

Explainer brings AI-powered document interpretation directly to the user's computer.

The application accepts document text, processes it through a local language model, and returns an explanation or structured analysis. Users can then ask follow-up questions to explore specific details.

The aim is to make document understanding more accessible while reducing dependence on cloud-based AI services.

## Features

### Plain-language explanations

Make complex information easier to understand without requiring specialist knowledge.

### Key information extraction

Identify important details, requirements, dates, monetary amounts, and instructions contained in a document.

### Actionable next steps

Organize relevant instructions into a checklist to help users determine what to do next.

### Natural-language questions

Ask follow-up questions about document content and receive answers generated by the local AI model.

### Local AI inference

Use LLaMA 3.2 1B through the QVAC SDK instead of sending prompts to a cloud-hosted language model.

### Privacy-focused design

The Node.js server binds to the loopback address `127.0.0.1`, restricting access to the local computer through the server's listening interface.

### Offline operation

After dependencies and model assets are available locally, the application is intended to support document analysis without an internet connection. This behavior should be verified on the target computer.

## How It Works

Explainer follows a local processing workflow:

1. **Input:** The user provides document text through the application.
2. **Validation:** The server checks the request and enforces input-length limits.
3. **Model initialization:** The application loads the QVAC SDK and initializes the configured LLaMA 3.2 1B model when AI processing is first requested.
4. **Inference:** The document content and relevant instructions are passed to the local model.
5. **Response processing:** Analysis output is parsed into structured sections when possible.
6. **Results:** The application returns the analysis or an answer to the user's follow-up question.

The server also exposes a status endpoint that reports model state, loading progress, errors, and the configured character limit.

## Technology Stack

| Technology | Purpose |
|---|---|
| Node.js | Application runtime and local HTTP server |
| QVAC SDK (`@qvac/sdk`) | Local model loading and inference |
| LLaMA 3.2 1B Instruct Q4_0 | On-device language model |
| HTML, CSS, JavaScript | User interface |
| Node.js HTTP module | Local API and static-file serving |
| Node.js test runner | Automated tests |

The project uses JavaScript ES modules and declares `@qvac/sdk` as its AI dependency.

## System Requirements

- A computer running Windows, macOS, or compatible Linux.
- Node.js compatible with the installed QVAC SDK.
- npm, installed alongside Node.js.
- Sufficient memory and storage for the model and application.
- Internet connectivity for initial downloads when dependencies or model assets are not already available.

Node.js 24.13.1 was used during development. Other versions should be tested for compatibility with the installed SDK.

A dedicated GPU is not specified as a requirement, but inference speed and memory usage will vary with the computer's hardware.

## Getting Started

### 1. Install Node.js

Download Node.js from the official website:

https://nodejs.org/

Open PowerShell on Windows, or a terminal on macOS/Linux, and verify the installation:

```powershell
node --version
npm --version
```

Both commands should display installed version numbers.

### 2. Obtain the source code

Clone the repository:

```powershell
git clone <YOUR_REPOSITORY_URL>
```

Enter the project directory:

```powershell
cd <YOUR_PROJECT_DIRECTORY>
```

Replace the placeholders with the actual repository URL and directory.

If you already have the source code, open your terminal in the directory containing `package.json` and `server.js`.

### 3. Install dependencies

Run:

```powershell
npm install
```

This installs the dependencies declared in `package.json`, including the QVAC SDK.

If the repository includes a synchronized `package-lock.json`, you can use the reproducible installation command:

```powershell
npm ci
```

### 4. Verify the project configuration

The project should contain the following essential files:

```text
qvac-test/
├── lib/
│   ├── prompt.js
│   └── validate.js
├── public/
│   └── index.html
├── server.js
├── package.json
└── package-lock.json
```

This is the expected structure based on the imports and paths in `server.js`; your actual project may contain additional files.

The `lib` directory supplies the analysis prompts and validation utilities. The `public` directory contains the frontend served by the application.

Ensure that the files imported by `server.js` exist before starting the server.

### 5. Start Explainer

The project's `package.json` defines the following startup script:

```json
"start": "node server.js"
```

Start the application:

```powershell
npm start
```

The server should listen on port `3000` at `127.0.0.1`.

Open your browser and navigate to:

http://localhost:3000

Keep the terminal open while using the application. To stop the server, press `Ctrl+C`.

### 6. Model initialization

The application loads the QVAC SDK dynamically and requests the LLaMA 3.2 1B Instruct Q4_0 model when inference is first needed.

The model-loading configuration in `server.js` specifies a context size of `32768` and reports loading progress through the status endpoint.

Ensure that the model assets required by the installed QVAC SDK are available locally. If the model has to be downloaded during its first initialization, complete that step before attempting an internet-disconnected run.

## Running Explainer

Once the application is running:

1. Open the local application in your browser.
2. Provide the document content using the available interface.
3. Request an analysis.
4. Review the generated explanation and key information.
5. Ask a follow-up question when you need clarification.
6. Verify critical details against the original document.

Start with a short text document to confirm that model initialization and inference work before testing larger inputs.

## Offline Testing

Offline functionality is a core objective of Explainer.

To verify it properly:

1. Install dependencies and make the model assets available.
2. Start the application while connected to the internet.
3. Confirm that the model loads and that a document can be analyzed.
4. Stop the application.
5. Disconnect Wi-Fi and other internet connections.
6. Restart the application.
7. Analyze new document content and ask a new follow-up question.
8. Confirm that both operations complete successfully.
9. Check logs and network activity for unexpected external requests.

A successful test must demonstrate new inference while offline, not merely show previously generated results.

If the application fails offline, inspect the error messages to determine whether a model asset, dependency, or another resource is still being fetched remotely.

## API Endpoints

The local server exposes the following endpoints.

### `GET /api/status`

Returns information about the current model state.

Example response:

```json
{
  "state": "ready",
  "progress": 100,
  "error": "",
  "maxChars": 10000,
  "promptVersion": "example"
}
```

The values above are illustrative; the actual character limit and prompt version are determined by the project's validation module and prompt configuration.

Possible model states include `not loaded`, `loading`, `ready`, and `error`.

### `POST /api/analyze`

Submits document text for analysis.

Example request:

```json
{
  "text": "Paste the document content here."
}
```

The server validates the text, loads the model if necessary, generates an analysis, and attempts to parse the response into structured sections.

The response includes a structured-result indicator, parsed results when available, detected document information, and processing time.

### `POST /api/ask`

Submits document text and a follow-up question.

Example request:

```json
{
  "text": "The document content goes here.",
  "question": "What are the most important requirements?"
}
```

The server checks that the document and question are valid, then generates an answer using the local model.

The question endpoint currently has a maximum question length of 1,000 characters. Document length is limited by the value defined in the validation module.

### Local server details

- Default port: `3000`
- Listening host: `127.0.0.1`
- Local application URL: `http://localhost:3000`
- Request content type: JSON for API requests

The server also limits request size and restricts accepted host and origin values.

## Privacy and Security

Explainer is designed to minimize exposure of document content to external services.

The server implementation:

- Binds to `127.0.0.1`.
- Runs model inference through the local QVAC SDK.
- Does not intentionally log document text when analysis fails.
- Returns API responses with `Cache-Control: no-store`.
- Validates input and enforces configured length limits.
- Attempts to unload the model during graceful shutdown.

These controls are useful privacy measures, but they do not independently prove that every component of the application is free from persistent storage or external communication.

Before making absolute privacy claims, review the frontend, model runtime, dependencies, logs, and temporary-file handling.

## Supported Documents

Explainer is intended to work with a range of document formats, including TXT, Markdown, PDF, and DOCX, where the frontend or associated local parsing implementation can extract their text.

The server's analysis endpoints receive **text**, rather than raw PDF or DOCX file contents. Consequently, file-format support depends on the document-reading functionality implemented in the rest of the application.

Potential limitations include:

- Scanned PDFs that require OCR.
- Password-protected documents.
- Corrupted files.
- Complex layouts, tables, and embedded objects.
- Very long documents that exceed the configured input limit.

## Troubleshooting

### `node` or `npm` is not recognized

Install Node.js, reopen your terminal, and run:

```powershell
node --version
npm --version
```

### The server cannot find a required module

Confirm that dependencies are installed and that the expected project files exist.

```powershell
npm install
```

Check that `lib/prompt.js` and `lib/validate.js` are present, as both are imported by `server.js`.

### The browser cannot connect

Check that the server started successfully and that port `3000` is available.

Open:

http://localhost:3000

If you changed the `PORT` environment variable, use the corresponding port instead.

### The model fails to load

Check that:

- The QVAC SDK installed correctly.
- Required model assets are available.
- The computer has enough available memory and storage.
- The installed SDK supports the model configuration used by the application.
- The terminal contains no additional model-loading errors.

### Analysis fails

Ensure that the document contains nonempty text and does not exceed the configured character limit.

If the model cannot complete inference, inspect the terminal for the underlying error while avoiding the disclosure of sensitive document content.

### Follow-up questions fail

Provide both the document text and a nonempty question. Keep the question within the 1,000-character limit.

If the application is still processing another request, wait for it to finish before retrying.

### Offline mode fails

Confirm that all dependencies and model assets were downloaded before disconnecting from the internet. Restart the application offline and inspect the model-loading error if initialization fails.

## Limitations

- AI-generated explanations may be inaccurate or incomplete.
- The quality of document interpretation depends on text extraction and model behavior.
- Long inputs may exceed the configured character limit.
- Complex or scanned documents may require additional parsing or OCR functionality.
- Local inference can be slower on computers with limited resources.
- Explainer does not independently verify the authenticity of a document.
- Users should verify important dates, financial amounts, eligibility requirements, and legal obligations against the original source.

Explainer is an assistant for understanding information, not a substitute for professional advice or independent verification.
